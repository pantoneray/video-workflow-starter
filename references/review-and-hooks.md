# 审核、钩子与安装规则（本地候选版）

本页描述可选审核方式及其实现边界。没有勾选或未给结论不等于通过；文件已生成不等于已提交，已接收不等于处理完成。

## 钩子二选一，不默认叠加

开工记录 `hook_mode = none | copy_frontload | packaging_preview`，未选择保持 none 并提供可选方案。

- 文案阶段：A 保存逐字原文及来源、前后文；B 只在获准范围内前置有吸引力的原内容。逐句记录 A 中位置、B 中位置、改字及理由，展示 A/B 供选择，不默认选择 B。A 不因 B 的编辑而改写。跨出处不拼成一段原话。
- 包装阶段：已审正文顺序保持，从真实成片选完整且有吸引力的一句作为前置预览，然后自然进入正片。记录原片入出点、重复范围、转场类型和成片预计/实测总时长。此处前置重复是明确选定的钩子方案，不是用循环补时长。
- 钩子目标约 3 秒，全片目标 30–45 秒，重复内容与转场均计入。句义、限定和真实停顿优先；完整句超出目标时换候选或交审核，不强切到 3 秒。
- 译文、音频、正文顺序或意味变化后递增稿件版本，重新译审/试听；不沿用旧通过。仅包装变更也需要新成片审核。
- 保存 `original_A`、`production_B`、`mapping`、`hook_mode`、`duration_basis`。原始资料、改稿及旧审批均不覆盖。

当前范围：脚本按标点分出供审核的完整句候选，显式选句后生成逐字A/B映射和T1页；不自动选择，不判断吸引力或语义独立。可选包装预览已提供本地开发入口，见[包装预览](hook-preview.md)，尚不代表生产闭环。

## 选文来源

用户可选“全集”“SRT 字幕”“自动”，未指定用自动。使用已有资料配置与索引，不另建全文库。便携离线入口为 `scripts/source_scope.py --source-type auto|corpus|srt`，复用 source_search，明确是关键词候选而不是 RAG/语义检索。现有 RAG 若已配置，应由其适配器先检索，再保留同样来源字段；本开发增量尚未连接项目 RAG。

沿用 life_corpus/deep_corpus 等已配置范围；SRT 可在 `paths.subtitle_sources` 配置。输出实际 searched_types/missing_types、文件哈希、章节或 SRT 时间码、上下文、重复出处记录。路径不可读或格式不支持就注明，不能声称两类都查过。任何结果都不是自动选文批准。

## 审核数据与执行

- T1 审 A/B 与来源；T2 审译稿和实际提供方的独立译、盲回译、差异；T3 审标题/封面文字/简介/标签及正文依据；T4 审真实成片。
- 一个 round 只有 local_html 或 notion 一个有效入口，绑定任务、语言、版本、内容哈希、逐条结论及意见。未审默认 pending；通过必须完成关键核对，需改必须有意见。
- T2 明确通过项独立准备 T3，不等需改项；T3 通过只批准文字，人工选图和成片验收另行完成。封面选图不得阻塞已具备其他条件的 HeyGen 校对上传。
- 协议：review_protocol；渲染：review_html；接收/归档：review_receipts + review_receiver；一次性处理：review_dispatch；下一表：review_advance。复用既有 translation_review/publication_assets，不安装第二套生产调度。
- 本地 receiver 明确启动才接收，默认只接收；配置 advance-output 后可执行已接通的后续处理。元数据模型调用需单独启用并配置。下载 JSON 不等于提交，无后台服务时不能承诺自动续跑。
- 当前仅 T2→T3 生成与返工请求经过模拟服务商测试；T1→译审、T3/T4→制作/上传仍未接通。不依赖外部调度框架，未附带自动生产集成。
- 不把内容审核收据当成付费或上传授权。未知外部结果先查原任务，绝不自动重发生成或上传。

## 回译和校对

Google Translate 为盲回译首选，Gemini 做独立翻译和校对；无 Google 凭据时前置失败，不回退 Gemini。维护方首轮真实通路是交接记录，各使用者仍须配置本人账户并验证语料效果；不能据回译直接覆盖审定稿。历史提供方不改标签。详情见[提供方状态](translation-provider-status.md)。

## 项目规则与安装

必要的项目级入口仅包含：视频任务读取本 Skill 及项目配置、已有文件不覆盖、逐版本审批与付费/发布授权分开、密钥不入库。仅对使用本包的项目生效。首次安装先检查现有 AGENTS，再展示待合并短段，冲突不覆盖、不重复插入；保留原文件备份。

具体模板、语种、术语、钩子、字幕布局、成本和媒体路径留在对应 Skill 引用或私密项目配置，不写入用户全局 AGENTS。Notion、Gemini、HeyGen、YouTube 按功能选择；本地选文/审核不能因未安装 Notion 被整体阻断。API key 仅使用环境或系统凭据。

现有 project init 只在项目 AGENTS 追加带标记的配置入口，保留旧正文；project sync 只更新项目记忆的受管配置区。尚未提供全局自动冲突合并/卸载命令。卸载时仅移除安装时增加的精确标记段及包本身，保留用户配置、素材、收据和旧项目规则；更新前备份，并核对引用版本。不得删除未知自定义内容。

## 验收边界

当前单元/HTTP/DOM 模拟测试证明相关数据处理行为，不等于浏览器视觉验收、真实服务商效果或另一台电脑安装成功。完整验证清单及当前限制由打包报告给出，未验部分留作后续更新，不作为阻塞其他已验证功能的依赖。

## 本地审核入口与存放位置

由 Codex 按 `review_protocol.py` 的数据约束，从当前实际稿件生成项目内的 round JSON；不可让待审核页面自行声明当前版本。先用 `workflow.py review-html --round 项目/审核/round.json --out 项目/审核/round.html` 生成页面，再显式运行：

```sh
python3 workflow.py review-serve --root 项目/审核记录 --round 项目/审核/round.json --page 项目/审核/round.html
```

打开终端打印的本机地址；直接打开 HTML 文件只能下载备用收据，不能提交给接收器。服务仅监听 127.0.0.1，停止终端服务后不再接收。

默认只接收，记录在 root 下的 `review-receipts.sqlite3` 与 `review-signals/`。显式启用后续处理需加 `--advance-output 项目/后续审核`；T2 生成发布资料还需本人允许模型调用并传 `--allow-metadata-model --metadata-model 本人可用模型`。处理成功后，审核快照和收据归档到 `reviews/`，入口为 `reviews/INDEX.md`；新 T3 文件路径记录在后续处理结果中。失败保留已完成项，核对状态后再重试，不重新上传或生成视频。

同一轮提交后要改意见或继续审核待审条目，应建立新轮次；重复提交相同结论返回同一收据，不能以修改时间绕过已提交记录。当前无后台自动监听或自动打开下一审核页。

## T2 展示证据绑定（rc.2）

T2 后续处理先核对页面数据中的中文稿、译文、回译、独立译文和差异说明与 `translation_version` 一致，且实际提供方标注非空，再写批准文件及请求元数据。提供方非空不等于验证了供应商身份，来源记录仍需审核。

当前该检查发生在后续处理时，页面尚无对应的前置阻断提示。收据已接收后可能出现处理失败；此时不代表已批准译文或生成 T3。保留收据，核对并修订任务及审核版本，不盲目重交。

## 查看处理状态

收到收据后，点击“查看处理状态”只读取对应收据，不重复提交、不调用模型。查询仅在本机接收器运行时可用，使用当前随机 token；服务停止时显示状态待核，不表示收据丢失。同标签页刷新可恢复本轮收据编号，仍需点击查询当前状态；下一张审核表按后续处理结果中的路径打开。

## 文案钩子候选入口

`python3 workflow.py hook-copy --source 项目/出处.json` 只列出候选，不选择、不批准。出处 JSON 包含源文件、哈希、字符范围、逐字原文和出处定位；脚本先核对来源。

明确选句后，提供 `--hook-index`（从0开始）、`--characters-per-minute`（源语种有效字符/分钟）、`--rate-basis`、`--task-id`、`--item-id`、`--batch`、新 `--version`/`--round-id` 和独立 `--out`，才生成 round.json 与 T1.html。有效字符复用语速脚本口径，含文字/字母/数字、不含空白标点；这仍是源文估算，不是目标语实测。超出约3秒或全片30–45秒时提示风险，不强截。

按上面的本地审核方式开启页面。T1明确通过后，仅保存 `selected-copy.json` 中实际选中的 A 或 B、出处、映射及收据，状态为等待翻译与独立复核。选择 A 保留原顺序、不开启文案钩子；不自动调用模型，不复用旧译文批准，不默认叠加包装预览。句界不证明指代、否定与逻辑独立，仍需人工判断。


## 本地页刷新恢复

同一浏览器标签页 sessionStorage 仅保存服务端已接收的64位收据编号，按任务/阶段/语言/轮次/版本/内容哈希/入口隔离，不保存正文、意见、审批选择或凭据。刷新后恢复查询按钮，状态先标待查询，用户点击后才读服务端；不自动重提或调用模型。新版本不继承旧收据。禁用浏览器存储仍能提交，只是不支持刷新恢复。关闭标签页、换端口或换浏览器不保证保留；此功能不是服务器账本的替代。DOM执行测试通过。维护方已报告真实浏览器隔离T3样本验收：提交一次需改后刷新，恢复编号、选项仍待审，POST保持1、GET为0；手动查询后GET为1。390px视口下长收据号溢出已用 overflow-wrap:anywhere 修复，复验 scrollWidth=clientWidth=390。本打包轮不重复实际提交；该证据仅限T3本次样本，不代表四模板全移动端验收。

## T4 本地成片播放

T4条目content.video填path与sha256，在review-serve中打开审核页即可播放本轮绑定的MP4。只打开离线HTML不会自动开放本地文件。服务只监听127.0.0.1，不支持远程分享；仅有随机临时入口的当前轮次/编号可读，不允许任意路径。每次媒体请求核验SHA，支持HEAD与单段Range拖动，旧轮次入口失效；大文件频繁拖动会增加本地哈希读取开销，尚未做多人并发优化。
播放、暂停和拖动不生成审核结论、不提交收据、不调用模型。服务停止后视频入口失效；重开服务由新审核页获得新的入口。维护方交接记录报告：真实32.636秒T4样本在浏览器静音播放和跳转13秒通过，readyState=4、无错误，仍待审；不代表声音听感、手机全片或用户批准。

本打包轮使用合成HTTP字节样本复验媒体协议，未重复播放私人视频或执行声音审核；私人素材不随包分发。

## 收据处理范围

review-dispatch仅处理当前任务/阶段/语言/轮次及内容哈希一致的已接收收据。其他任务保持原状态；同轮旧哈希只报告stale_current_round_receipts，不调用续跑、不改成失败、不迁移批准。no_change时仍应查看该异常列表。既有单轮配置保持兼容，不新增定时器。

# Notion 审核接入检查

Notion是可选入口。本地HTML审核不需要Notion账号。选择Notion时，需要使用者自己的工作区账号、获准访问审核页的API连接，以及能实际编辑该页面的审核人。把已有审核页共享给连接；404也可能是工作区或共享权限不匹配，不要直接认定页面删除。

API连接凭据通过本机安全配置注入NOTION_API_KEY，不贴聊天、不写个人配置JSON/代码/收据，不复制维护者账号。桌面连接器授权不会自动成为这个独立Python脚本的凭据；已有连接器能读页面也不证明同事设备已配置。

```bash
python workflow.py notion-check --page-id <已共享的审核页ID> --out ./notion-read-check.json
```

此命令只调用官方GET users/me、pages与block children，输出实际bot ID、工作区名及指定页读取结果。使用现有2022-06-28兼容API版本；网络超时20秒，读请求最多3次指数退避，401/403/404不反复重试。日志不含密钥或服务端原始错误。输出文件须不存在，避免覆盖历史。没配置密钥时不请求网络。

`read_access_verified`仅表示指定页与其首批内容可读：不代表全文已读、审核人身份已验证、写权限已测、T1–T4收据适配已上线或通过后自动续跑。当前通用包Notion新适配仍未启用；不要仅靠“看完了”复选框批准所有条目，也不要让HTML与Notion同时成为同轮有效入口。

下一接入必须把现有页的逐条结论/意见/关键核对项映射到统一review_protocol，绑定当前稿件哈希，使用同一Receipts账本与既有调度。没有完整映射及回读验证前，不切换生产入口、不新增定时器。只需本地审核的同事可以跳过本节。

参考官方接口：[连接身份](https://developers.notion.com/reference/get-self)、[读取页面](https://developers.notion.com/reference/retrieve-a-page)、[读取内容块](https://developers.notion.com/reference/get-block-children)。

2026-11-17：离线权限/重试/不泄漏凭据测试通过；维护者现有工作区和流程页已做真实只读验证，无写入。本包不携带该凭据、页面ID或真实回执，使用者须自行运行检查。

开发中：notion_review_adapter提供注册块到统一收据的纯校验器，要求当前round、显式审核人ID、可见稿件与绑定一致、逐条结论/检查、整轮提交时间顺序。它本身不读取Notion、验证HTTP来源或入账；导出JSON不能作为认证审批。注册/分页读取/真实提交闭环未验收，不能仅调用该函数就启用Notion生产审核。

开发接线补充：notion_review_ingest现在可按注册ID通过官方GET直接读取块、验证所属页面并两遍比对，交给现有Receipts账本；不受整页分页遗漏影响。未提交即退出，重复入账不创建新收据。离线与临时账本测试已有验证；维护方另报告隔离需改样例联通（见下文），真人批准和通用页面注册尚未验收，默认不启用生产。

一致性比较注意：Notion官方GET每次可能附不同request_id，它是请求元数据，应排除；正文、字段类型、归属页、编辑人及编辑时间仍完整比较。API的last_edited_by也可能是授权连接器代表的用户ID，不能单凭该字段宣称真人亲手审批。生产规则必须禁止自动写批准，保留实际用户审核来源；测试样例需显著标记并隔离账本。

维护者真实隔离验证：显著标注的需改样例经过官方读取→统一收据→现有返工分流→归档/索引，1张账本、0待处理信号，无模型/生成/上传。样例由连接器写入，不是本人真实审核；批准分支、通用页面创建和生产开关仍未验。重复capture网络失败不删除/重放已有收据，报告capture_failed并保留原处理状态。

统一入口：`python3 workflow.py notion-ingest --round <当前轮次.json> --registration <本机登记.json> --root <隔离收据目录>`。登记必须来自可信当前轮次与显式审核人配置；本包尚无普通使用者的页面注册界面，不要求使用者手工构造登记来替代该缺口。接收只写本地收据，后续处理另由既有 review-dispatch 执行。
